AstroNbodySim.jl

A general-purpose, GPU-accelerated astrophysical N-body simulation library, released under the GPL-3.0 license.

AstroNbodySim.jl builds on the broader JuliaAstroSim ecosystem (PhysicalParticles, PhysicalTrees, PhysicalMeshes, AstroIC, AstroIO, AstroPlot, ParallelOperations) to provide a modular, fully unit-aware, hybrid-parallel simulation toolkit.

Installation

]add AstroNbodySim

or, to install from the latest main branch:

]add https://github.com/JuliaAstroSim/AstroNbodySim.jl

You might need to install NVIDIA CUDA toolkit

Package Features

  • Compute with units
  • User-friendly
    • Well documented
    • Readable programming
    • Vectorized array operations
    • Dispatch on types for various simulation settings
    • Float16, Float32, Float64, Int128, BigFloat, Measurement, etc.
  • Cross-platform: Linux, Windows, MacOS. Easy to deploy
  • Hybrid Parallelism: multi-threading, distributed parallelism, GPU acceleration
  • Modularity and Versatility: 10+ packages, designed for general purposes, highly extentable
  • Realtime visualzation (interactive)
  • Auto-test workflow

Development Guide

  1. It is highly recommended to use latest master branch of related packages (in JuliaAstroSim), first clone:
    • ParallelOperations.jl
    • PhysicalParticles.jl
    • AstroIO.jl
    • AstroIC.jl
    • PhysicalTrees.jl
    • PhysicalMeshes.jl
    • AstroPlot.jl
  2. dev --local [absolute path] to install packages mentioned above, for example
    pkg> dev --local /home/user/work/AstroNbodySim
  3. VS Code as well as its Julia Extension is convenient to use, and Revise.jl will update changes on the run.

First Time User Guide

  1. Read documentation of Julia: https://docs.julialang.org/en/v1/

  2. Read documentations and READMEs of related packages

  3. Try examples in AstroNbodySim/examples. First install packages used in examples by AstroNbodySim/examples/install_pkgs.jl. The default output directory of all examples is ./output. The programme would make a directory if the user-defined output path does not exist to avoid unnecessary errors.

  4. To interrupt a running simulation, create a file named stop in the output directory (same with Gadget2):

    echo > output/stop

  5. It's convenient to check out supported function arguments and keywords by help? in REPL, for example,

    help?> run
search: run

  run(sim::Simulation)

  This function does all the work for you:
  1. `prepare` sim environment and preprocess data
  2. evaluate force, initialize timesteps, output
  3. `mainloop`

Gravity solvers at a glance

SolverMethodComplexityTypical use
DirectSumsoftened pairwise summation$\mathcal{O}(N^2)$reference solutions, $N \lesssim 10^5$
TreeBarnes–Hut octree (Gadget-2 framework)$\mathcal{O}(N \log N)$large particle counts, $N \gtrsim 10^5$
FFTspectral Poisson solver on a mesh$\mathcal{O}(N_g^3 \log N_g)$periodic boxes, 3D galaxy simulations
FDMfinite-difference Poisson solversparse/dense linear solve1D/2D verification, non-periodic boundaries
MLneural-network Poisson solver (experimental)network inferenceresearch prototype only

The particle solvers use the Gadget-2 cubic-spline softening kernel and the Gadget-2 leapfrog (kick–drift–kick) integrator, with fixed or adaptive timesteps. See the Manual for the formulas, defaults and parallel execution modes.

Relation to WaveDM.jl

AstroNbodySim.jl also provides the N-body engine used by WaveDM.jl. There the DirectSum and Tree solvers are used for collisionless baryons (bulge and stellar disk particles). In the static (:particles_static) mode the particle set is frozen and only supplies a background potential; in the dynamic (:particles_dynamic) mode the particles contribute their potential to the grid at every SPE step and the wave-DM acceleration is interpolated back to the particle positions. The baryon_mode keyword itself belongs to WaveDM.jl, not to this package. Orbit lookback and tidal-force workflows built on these solvers are demonstrated in examples/08-TrajectoryLookback.
